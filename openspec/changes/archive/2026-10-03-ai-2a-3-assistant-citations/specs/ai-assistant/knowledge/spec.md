## MODIFIED Requirements

### Requirement: Replies are grounded in the product documentation
When the installation uses the static knowledge source (the default), the system SHALL give
the model the product documentation corpus when generating every reply, placed after the
assistant's fixed instructions and before the user context, the conversation history and the
question, so that the stable part of the prompt forms a common prefix across turns. When the
installation uses retrieval from the PostgreSQL index, grounding follows
`ai-assistant/knowledge-citations` instead and the static corpus is not sent.

#### Scenario: Reply is generated with knowledge
- **WHEN** a reply is generated for any question in static mode
- **THEN** the backend receives the assistant instructions first, then the documentation
  available to that user, then the user context, then the history, and the question last

#### Scenario: Two turns of the same user share the knowledge prefix
- **WHEN** the same user asks two questions with the same knowledge version in static mode
- **THEN** the instructions and documentation sent to the backend are identical in content and
  order for both turns

#### Scenario: Retrieval mode does not send the static corpus
- **WHEN** a reply is generated with the PostgreSQL knowledge source
- **THEN** no static corpus document is sent to the backend

### Requirement: Knowledge carries no tenant data
In static mode the documentation given to the model SHALL be static product documentation that
is identical for every tenant. In every mode the documentation given to the model SHALL NOT
contain or be derived from any tenant's records, users or settings.

#### Scenario: Two tenants ask the same question
- **WHEN** users with the same role in two different tenants ask a question under the same
  static knowledge version
- **THEN** the documentation sent to the backend is identical for both

### Requirement: The knowledge a reply used is recorded
The system SHALL record on each generated reply the version of the knowledge it was generated
with. In static mode the version SHALL be a deterministic function of the corpus content — the
same content yields the same version and any content change yields a different one. In
retrieval mode the version SHALL identify the published source revisions of the selected
excerpts. The full prompt SHALL NOT be stored. A reply created before versions were recorded
SHALL remain valid with no version.

#### Scenario: Reply records its knowledge version
- **WHEN** a reply is generated
- **THEN** the stored reply carries the version of the knowledge that was sent to the backend

#### Scenario: Retried reply keeps an accurate version
- **WHEN** a reply is regenerated by a later attempt
- **THEN** the stored version is the one used by the attempt that owns the reply, written under
  the same ownership rules as the reply's other state

#### Scenario: Unchanged documentation keeps its version
- **WHEN** the static corpus is regenerated from unchanged documentation
- **THEN** its version is unchanged
