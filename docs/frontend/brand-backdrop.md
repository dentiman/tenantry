# Брендовий фон і скляний шел

> Прототип, 2026-09-26. Один споживач — `/guide`. Звичайні робочі екрани (гріди,
> форми, календар) **не змінюються** і лишаються на суцільних поверхнях теми.
> Код — `libs/ui/src/brand-backdrop.css` + `libs/ui/src/components/brand-backdrop.tsx`.

## 1. Навіщо

Перехід на «вітринну» сторінку (путівник, майбутній дашборд-вітрина) виглядав як та сама
сіра CRM: полотно `--background`, сайдбар `--sidebar`, картки `--card` — чотири непрозорі шари,
під якими будь-який фон просто не видно. Мета — щоб такі сторінки мали брендовий фон на все
вікно, а шел (рейл, панель area, хедер, бічні панелі) лишався тим самим шелом, тільки скляним
поверх фону.

Рамка рішення: **фон — властивість роуту, а скло — перевизначення токенів**. Компоненти не
знають про фон нічого, кольори живуть лише в CSS (§7 `theming.md`).

## 2. Референс

DeepSeek Harness (`https://www.deepseek.com/harness/en/`), значення зняті з живої сторінки
(CSS-змінні `--ds-*` і canvas):

| Що                | DeepSeek                                                                  | У нас                                                  |
| ----------------- | ------------------------------------------------------------------------- | ------------------------------------------------------ |
| Основа            | `#0a0a0a`                                                                 | холодний майже-чорний / майже-білий (`--backdrop-base`) |
| Візерунок         | лінійна сітка 90px, 1px білого ≈4%, на canvas з анімацією                   | **точки** лише в місцях плям, чистий CSS, без анімації  |
| Плями             | 3 радіальні градієнти `#1a3870`→`#4a8ac4`, `blur(60…100px)`, `opacity .2….4` | 3 плями, колір **виведений з `--primary`**             |
| Поверхні          | біле скло 2…6% + inset-хайлайт зверху 12%, `blur 12px`                     | скляні токени + `--glass-highlight`                    |

Чому точки, а не сітка: лінійна сітка складалася з тих самих 1px-ліній, що й межі шела
(сайдбар, хедер, картки), і зливалася з ними — інтерфейс і фон читалися одним візерунком.
Точки з межею не сплутаєш. Решта розглянутих варіантів (зерно, штрихування, промені,
топографія, mesh), посилання на приклади і дослідження «глобуса з точок» —
`docs/frontend/brand-patterns-research.md`.

## 3. Як увімкнути на сторінці

```ts
const guideRoute = createRoute({
  getParentRoute: () => appRoute,
  path: '/guide',
  component: GuidePage,
  staticData: { backdrop: 'brand' },
});
```

Тип — `StaticDataRouteOption.backdrop` у `router.tsx`, поруч із `layout: 'padded' | 'bleed'`
і з тієї самої причини: це статична властивість екрана. `AppShell` читає
`useMatches().at(-1)?.staticData.backdrop` і робить дві речі:

1. ставить `data-backdrop="brand"` на обгортку `SidebarProvider` — від цього атрибута
   перевизначаються токени (§4);
2. рендерить `<BrandBackdrop />` **першою дитиною** `SidebarProvider` і **без `z-index`**.
   Так шар фону (`position: fixed`) малюється під фіксованим контейнером сайдбара (`z-10`) і
   під `SidebarInset` (`relative`, пізніше в DOM). Від'ємний `z-index` не годиться: фон пішов
   би під непрозорий `body`.

Портальні оверлеї (`Popover`, `Dialog`, `Sheet`, мобільний сайдбар у `Sheet`) рендеряться в
`body`, **поза** обгорткою, тож лишаються суцільними — і це правильно: попап над склом мусить
читатися.

## 4. Токени

### 4.1 Фон (`:root` / `.dark`)

| Токен                      | Світло                       | Темрява                         | Що                                      |
| -------------------------- | ---------------------------- | ------------------------------- | --------------------------------------- |
| `--backdrop-base`          | `oklch(0.985 0.006 255)`     | `oklch(0.155 0.012 258)`        | колір під усім                           |
| `--backdrop-dot`           | `--primary` 10%              | білий 5%                        | **прозорість точок** — крутити тут       |
| `--backdrop-glow-1/2/3`    | `--primary` 32/18% + білий, бірюза | `--primary` 70/45% + чорний, бірюза | кольори трьох плям                  |
| `--backdrop-glow-opacity`  | `0.2`                        | `0.5`                           | непрозорість плям                        |
| `--glass-highlight`        | білий 70%                    | білий 6%                        | inset-лінія зверху картки                |

У темряві плями — не яскравий `--primary`, а його глибокий «нічний» відтінок (так робить
DeepSeek: `#1a3870` при бренді `#6799fe`). Бренд міняється в темі чи в тенанта — фон
міняється разом із ним.

Геометрія точок — правило `.brand-backdrop__dots`: крок `background-size: 12px`, точка
`1.5px` (край згасає до `2px`). Маска — три еліпси з центрами плям; **пересуваєш пляму —
переносиш і її еліпс**, інакше точки опиняться на нейтральному фоні.

### 4.2 Скло (`[data-backdrop='brand']`)

| Токен / правило                         | Значення                                       | Кому                                   |
| --------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| `--background`                          | `transparent`                                  | полотно `SidebarInset`                  |
| `--sidebar` ← `--sidebar-glass`         | `--sidebar` 62% + `blur(24px) saturate(1.4)`   | рейл + `AreaSidebar`, `ContextPanel`, `AiPanel` |
| хедер `[data-slot=app-header]`          | `--backdrop-base` 30% + `blur(16px)`           | верхній хедер контенту                  |
| `--card` ← `--card-glass`               | `--card` 60% + `blur(6px)`                     | картки; «заплановані» в гіді — `bg-card/50` |
| `--border`, `--sidebar-border`          | `--foreground` 10%                             | межі (5.5% темряви губились на склі)    |
| `--secondary` ← `--accent`              | накладка `--foreground` 9.4 / 11%              | бейдж і кнопка `secondary`              |
| `--muted`                               | накладка `--foreground` 6%                     | плитки іконок у картках                 |

Два прийоми, без яких це не працює:

- **Скляні токени оголошені на `:root`**, а під `[data-backdrop]` лише підставляються
  (`--sidebar: var(--sidebar-glass)`). Custom property розв'язує `var()` там, де її оголошено,
  і нащадки успадковують готовий колір. Пряме `--sidebar: color-mix(… var(--sidebar) …)` на
  тому самому елементі — цикл, і токен мовчки стає невалідним. Працює тому, що Tailwind 4
  мапить токени через `@theme inline` (утиліта підставляє `var(--sidebar)` напряму).
- **Накладки замість суцільних сірих.** `--secondary`/`--muted` у темі — суцільні `#2f2f2f`/
  `#262626`; на кольоровому фоні вони читалися латками чужої теми. Накладка кольору тексту
  (модель `--accent`, §1.3.3 `theming.md`) бере відтінок плями під собою.

Свідомий виняток: **активний таб лишається суцільним** (`--segment`, інверсія в темряві,
§1.3.4 `theming.md`) — інакше вибране втратило б виразність.

## 5. Граблі

- **`AreaSidebar` — `Sidebar` усередині `Sidebar`.** Два шари по 62% дали б колонку area
  помітно щільнішою за рейл, тому вкладений `[data-slot=sidebar]` під склом прозорий, скло
  одне — на `sidebar-inner`.
- **Кожна бічна колонка має бути в списку блюру.** `AiPanel` спершу туди не потрапила: фон 62%
  без блюру показував точки й плями чітко, і панель читалась «прозорішою» за сайдбар, хоча
  непрозорість однакова. Нова колонка шела → її `data-slot` у правило `backdrop-filter`.
- **Блюр і прокрутка.** Сайдбар і хедер нерухомі над нерухомим фоном — блюр рахується раз.
  Картки їдуть при прокрутці, і фільтр перераховується щокадру, тому в них мінімальний радіус
  (6px). Перше, що прибрати, якщо довга сторінка почне смикатися на слабкій машині.
- **Непрозорість сайдбара залежить від того, що під ним.** Скло над майже-білим лише
  розмиває білий — світлий сайдбар виглядав суцільним. Велику пляму перенесено ліворуч, під
  сайдбар: тоді скло отримує відтінок і читається склом.
- **Контент не проїжджає під хедером.** Хедер стоїть поза `ScrollArea`, тож його блюр розмиває
  лише фон. Класичний ефект «картки пропливають під матовим хедером» потребує покласти хедер
  поверх скролера — окрема правка шела.

## 6. Відкрите

- Прототип перевірено обчисленими стилями в браузері, не скріншотами; світлу тему варто
  переглянути очима окремо.
- `apps/platform-web` фон не підключав (компонент і CSS у `libs/ui`, тож підключення — це
  `staticData` + ті самі три рядки в його `app-shell.tsx`).
- Тема `slate` не оголошує `--backdrop-*` окремо — бере значення дефолту; скляні токени
  виводяться з її власних `--sidebar`/`--card`, тож скло в неї своє.
- Display-шрифт для hero вітринних сторінок (DeepSeek: Host Grotesk / Montserrat 46px, 500) —
  не робився.
