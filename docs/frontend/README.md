зруйнувати зв'язність:

| Документ                                                                                   | Що там про фронт                                                                                                  |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| [`../error-handling.md`](../error-handling.md)                                             | `parseApiError`/`isGlobalApiError`, канали реакції (тост / поле форми / refresh-інтерсептор), `applyServerError`  |
| [`../i18n-plan.md`](../i18n-plan.md)                                                       | react-i18next на фронтах, `libs/i18n` проти фічевих локалей, доктрина «бекенд віддає коди, текст рендерить фронт» |
| [`../notifications.md`](../notifications.md)                                               | дзвінок із бейджем, `Drawer`, `NotificationCard` як один компонент для тоста і центру, два регіони тостів         |
| [`../activity-log.md`](../activity-log.md)                                                 | `ActivityFeed`/`ActivityMessage`, рендер типу події через `<Trans>`                                               |
| [`../realtime.md`](../realtime.md), [`../realtime-internals.md`](../realtime-internals.md) | клієнт Socket.IO як singleton поза React-деревом, `PresenceDot`, патч snapshot-а за правилом трьох ревізій        |

## Дизайн-джерела

`design/` тримає джерела дизайн-канв (`.dc.html` + `canvas.json`) поруч із документом, який
пояснює прийняті рішення. Причина та сама, що і в решти `docs/`: рішення живе в репозиторії, а
не в чужому сервісі, і переживає зміну інструмента. Зібрані канви (~2 МБ, редактор усередині)
не комітяться — тільки джерела і посилання на опубліковану канву.

## Відкриті питання

Те, що потрібно з'ясувати або вирішити. Все, що вже вирішено, живе в `ui-stack.md` (правила)
і `ui-migration-history.md` (рішення міграції).

### Потребують рішення користувача

| #   | Питання                                                                                                                                                                                                                           |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **`pnpm format:check` червоний** — 79 файлів, усі поза UI-роботою (зокрема `libs/shared/**`). Репозиторний `pnpm format` одним комітом ховає диф будь-якої поточної роботи, тому не робився. Коли і чи прогонити?                 |
| 2   | **`country-flag-icons` — 189.9 KB, тобто 61% CSS-бандла `apps/web`** (257 інлайн-SVG прапорів заради поля телефону). Лишаємо як є, вантажимо на вимогу, чи міняємо на емодзі-прапори / підмножину країн?                          |
| 3   | **Ліцензія ReUI.** Реєстр `@reui` прописаний, але всі блоки віддають 401. Купувати чи закрити напрям? Якщо купувати — правило вже зафіксоване (`ui-migration-history.md` §3.10: блоки в застосунок, не в `libs/ui`).              |
| 4   | **Хардкод «Close»** у вендорених `DialogContent`/`SheetContent` (`<span className="sr-only">Close</span>`). Прийнятий як єдиний легальний хардкод; альтернатива — локальна правка з `useTranslation` у вендореному шарі. Лишаємо? |
| 5   | **Фронтових тестів немає взагалі.** У roadmap стоїть «Vitest для критичних фронтових флоу», але фази немає. Приймання UI досі робилось вимірюванням у DOM через headless-браузер вручну. Заводити? **Черга вже конкретна** (усі писались чистими саме під тест, усі без раннера): `layoutOverlaps`, `snapDelta`/`applyDrag`, `minutesAtOffset`/`draftRange`, `resolveHotkey`, `defaultCreateStart` у календарі — комбінацію «протягнули вгору через межу переходу на зимовий час» оком не перевіриш. |

### Технічні розбіжності, які варто закрити

| #   | Питання                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 6   | **Дві конвенції імпорту всередині `libs/ui`.** 41 файл використовує самопосилання `@saas-skeleton/ui/…` (документована монорепо-форма shadcn), а три файли, що переїхали 2026-08-26 (`page-breadcrumbs.tsx`, `lib/error-toast.ts`, `lib/format.ts`), — відносні шляхи. Яку фіксуємо? Самопосилання потрібне, щоб `shadcn add` сам переписував імпорти. |

### Готовий код без споживача

Не проблеми — заготовки, які варто пам'ятати, щоб не переписати їх удруге:

| #   | Що                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7   | **Вибір рядків гріда в `platform-web` не спожитий** — жоден `Grid.Root` там не вмикає `selection`. Перший реальний споживач зʼявиться з доменними сторінками.                                                                                                             |
| 8   | **Проп `actions` у `DataGridFilters`** — місце праворуч у тулбарі під майбутній перемикач видимості колонок. Сам перемикач (`DataTableViewOptions` у shadcn-admin) свідомо не брали: колонки в нас статичні.                                                              |
| 9   | **Місце під назву тенанта** (MT-4). У `apps/platform-web` це підзаголовок у `SidebarHeader` (`layout.brandSubtitle` — «Control plane»); у `apps/web` підзаголовок знятий: у смузі 48px влазить лише плитка, і назва тенанта приїде дропдауном на ній (`app-shell.md` §5). |

### Не перевірено людиною

Приймання UI робилось вимірюванням у DOM. Поза автоматикою лишились: субʼєктивна оцінка
типографіки й щільності, поведінка на вузьких екранах, робота з реальним скрінрідером.
