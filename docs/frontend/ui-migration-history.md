# Історія міграції UI

**Міграція завершена і прийнята 2026-08-24.** Обидва фронти на shadcn/ui (Base UI), спільний
шар — `libs/ui`, попередня UI-бібліотека видалена з репо повністю: немає ні імпортів, ні
залежностей у `package.json`/`pnpm-lock.yaml`, ні MCP-сервера, ні скіла, ні токенів у розмітці.

Цей документ — **факт і його наслідки**, не план. Поточні правила стека — `ui-stack.md`;
плани й покрокові журнали виконання видалені разом із завершенням роботи.

## 2. Чому пішли з попередньої бібліотеки

Не смаки. Вона була в бета-статусі, і її форм-контроли (`Switch`, `Checkbox`) **не
перемикалися від дій користувача** — жодної помилки в консолі, контрол просто мертвий.
Відтворювалось і поза таблицею, і на сирому шарі, на якому та бібліотека стояла; нативний
`<input>` на тій самій сторінці працював. Через це в гріді довелося тримати два костилі:

1. інертний візуал бібліотеки з прозорим нативним `input` поверх нього на всю площу;
2. `createPortal` хедер-чекбокса в `<thead>` (з `rootRef`, `setTimeout` і `useEffect`).

Обидва зняті — під Base UI працює штатний `Checkbox` з `indeterminate`. Це і була головна
метрика успіху міграції.

## 3. Рішення, ухвалені під час міграції і чинні досі

| #   | Рішення                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **Один стек на обидва фронти.** Проміжне рішення «дві бібліотеки, по одній на застосунок» переглянуте користувачем 2026-08-24 і скасоване.                                                                                                             |
| 2   | **`lucide-react` прийнято повністю** — перегляд попереднього правила «без пакетів іконок, інлайн-SVG». Компоненти реєстру приходять з lucide у своєму коді; вичищати вручну означало б вічно конфліктні `add --diff`. ≈80 рядків власних SVG видалено. |
| 3   | **Стиль `base-nova`.** ReUI **не використовуємо** (блоки платні), але реєстр `@reui` прописаний у `components.json` — щоб компонент звідти був одним `add`, якщо колись знадобиться.                                                                   |
| 4   | **ReUI DataGrid як каркас відкинутий.** Він на TanStack Table (клієнтська модель колонок/сортування/пагінації), а наш грід — headless-шар під **серверну** колекцію з URL-фільтрами. Заміна каркаса = перепис контракту.                               |
| 5   | **Драйвери — `sheet`, а не `drawer`.** Наші панелі керовані ззовні (`isOpen`/`onClose`) і без жестів; `drawer` приніс би контекст snap-points, який нічим заповнити.                                                                                   |
| 6   | **Сайдбар — реєстровий `Sidebar*`**, не рукописний `<aside>`. Ціна — 730 рядків вендореного коду; платиться один раз на обидва фронти, бо компонент у `libs/ui`.                                                                                       |
| 7   | **`FileDropzone` лишається наш** (дропзони в реєстрі немає), але оболонка складена з `Empty` + `Button` — костиль `role="button"` + `tabIndex` + `onKeyDown` на `<div>` зник.                                                                          |
| 8   | **`libs/ui` витягується ПЕРЕД міграцією основного застосунку**, а не після: 9 із 29 файлів web були дослівною копією вже мігрованих, і пакет перевірявся проти вже прийнятого platform-web.                                                            |
| 9   | **Мертвий код видалений разом із міграцією**: проп `variant` у `FormTextField`/`FormPasswordField` (жоден викликач не передавав), `CellSwitch` (існував виключно як костиль).                                                                          |
| 10  | **Якщо колись купимо ліцензію ReUI** — блоки тягнути **в застосунок**, а не в `libs/ui`, і перевіряти, чи не тягнуть вони `@reui/*` примітиви: це був би другий набір базових компонентів поруч із нашим.                                              |

## 4. Кустарний код, який замінили реєстровими примітивами

Головний обсяг роботи був не в імпортах, а тут — 14 місць:

| Було                                                               | Стало                         |
| ------------------------------------------------------------------ | ----------------------------- |
| Інертний чекбокс під прозорим нативним `input`                     | штатний `Checkbox`            |
| `createPortal` хедер-чекбокса в `<thead>`                          | звичайна розмітка `TableHead` |
| `CellSwitch` (той самий костиль для тумблера)                      | `Switch`                      |
| `measureAnchor()`, `crossOffset`, перевизначення `--trigger-width` | `ComboboxContent anchor`      |
| `role="button"` + `tabIndex` + `onKeyDown` на `<div>` дропзони     | `Empty` + справжня `Button`   |
| те саме в картці сповіщення                                        | `Item render={<button/>}`     |
| ручний медіа-обʼєкт (`min-w-0` / `truncate` / `title`)             | `Item*`                       |
| абсолютний `<span>` + `title` для presence                         | `AvatarBadge` + `Tooltip`     |
| порожні стани як `<p class="py-8 text-center">`                    | `Empty*`                      |
| три `Button` із ручним `variant`                                   | `ToggleGroup`                 |
| рукописний `<aside class="w-60">`                                  | `Sidebar*`                    |
| `bg-transparent! p-0! shadow-none!` на тості                       | власна композиція `Toast`     |
| інлайн-SVG у 5 файлах                                              | `lucide-react`                |
| `border-e-0` / `pe-1` / `ps-1` у полі телефону                     | `InputGroupAddon`             |

## 5. Граблі, які варто пам'ятати

Ті, що лишились актуальними правилами, переїхали в `ui-stack.md` §7 (бекендні tsconfig-и,
override zod, формат лок-файла, перевірка в браузері). Тут — специфічні для самої міграції:

- **Механічна заміна імен токенів дає два типи тихих регресів.** «Клас зник» (утиліти не існує,
  Tailwind її не генерує, елемент лишається нефарбованим) — помітно. «Клас лишився і означає
  інше» — найгірший випадок: сторінка виглядає майже нормально. Тому свіп робився не як мапа
  «старе імʼя → нове», а як мапа **ролей** («роль у застосунку → токен»); результат живе в
  `ui-stack.md` §3.
- **Як перевіряли, що свіп повний**: усі `--color-*` старої бібліотеки **мінус** токени нашої
  теми = список мертвих імен, далі grep розмітки з префіксами
  `bg|text|border|ring|outline|divide|fill|stroke|shadow|from|to|via`. Плюс окремо два «тихі»
  випадки, які цим grep-ом не ловляться. Прийом себе виправдав — нічого поза мапою не
  знайшлось.
- **Порядок «переключити на пакет → потім свіп»**, а не навпаки: інакше чистиш файли, які за
  годину видаляються.
- **Міграція сама породжує невалідний HTML.** Два випадки: `<p>` у `<p>`
  (`AlertDialogDescription` уже абзац) і `<button>` у `<button>` (картка сповіщення в
  `plain`-режимі сама є кнопкою). React пише про це в консоль — правило винесене в
  `ui-stack.md` §4.
- **`shadcn init` не перезаписує наявний `index.css`, а дописує свій блок** — старі
  override'и треба прибирати вручну.
- **У CLI 4.19.0 пресет зветься `nova`**, а не `base-nova` (`base-nova` приймає лише
  `--defaults`); база передається окремо `-b base`. У `components.json` при цьому лягає
  `"style": "base-nova"` — мета досягнута.
- **Теми реєстру `@shadcn` для стилю `base-nova` не опубліковані** (`theme-slate` → 404), а
  іменовані пресети (`nova`, `vega`, `maia`, `lyra`, `mira`, `luma`) — варіації того самого
  нейтралу. Власну палітру довелося прокладати вручну; вийшло дешево, бо тема після UI-0 —
  один файл.
- **Перед тим як тягнути компонент з іншого реєстру — перевір, чи потрібна поведінка не є
  пропом у нашому.** `alignItemWithTrigger` виявився в обох реалізаціях `select`, бо це проп
  Base UI, а не фіча бібліотеки. З чужого реєстру варто брати не файли, а точкові прийоми.

## 6. Виміряний результат

| Метрика                                                 | Результат                                                                           |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Костилі гріда                                           | 2 → 0 (`grep createPortal\|inert\|SelectionCheckbox` — порожньо)                    |
| CSS `platform-web` (на момент зняття старої бібліотеки) | 410.4 KB → 77.5 KB (**−81%**)                                                       |
| JS `platform-web`                                       | 1077.0 KB → 937.2 KB (−13%)                                                         |
| CSS `apps/web` після всіх ходів                         | 316.8 KB, з них **189.9 KB (61%) — `country-flag-icons`** (257 інлайн-SVG прапорів) |
| Файл `data-grid.tsx`                                    | коротший на ≈90 рядків                                                              |

Приймання робилось **вимірюванням у DOM** через headless-браузер, а не скріншотами: токени й
геометрія, `aria-sort` на `<th>`, `aria-checked="mixed"` у шапці гріда, позиції двох регіонів
тостів, ширина попапа країн проти ширини поля, живий цикл Suspend/Resume, живий тост
сповіщення з воркера, синхронізація прочитаного між вкладками. Консоль без помилок на всіх
сторінках обох застосунків.

Що **не** перевірялось автоматикою і лишається за людиною: субʼєктивна оцінка типографіки й
щільності, поведінка на вузьких екранах, робота з реальним скрінрідером.
