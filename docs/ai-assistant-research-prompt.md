# Промпт: дослідження AI-асистента (бічний LLM-чат) — етап 2

Продовжуєш дослідження фічі «AI-асистент» для tenant-порталу цього SaaS-скелетона.

**Не читай `docs/ai-assistant.md` і не шукай його в репозиторії.** Цей файл самодостатній:
усе, що потрібно знати про вже ухвалені рішення, — у списку нижче. Не переглядай і не
пропонуй альтернатив пунктам у цьому списку — вони зафіксовані користувачем і закриті.

## Зафіксовані рішення (дано, не обговорювати заново)

- **Область** — тільки tenant-портал (`apps/web`), під наявною JWT-авторизацією. Публічної
  (неавторизованої) зони немає.
- **UI** — нова персистентна не-модальна поверхня шела, `AiPanel`: п'ятий сусід
  `AppRail`/`AreaSidebar`/`SidebarInset`/`ContextPanel`, з самого правого краю вікна (правіше
  за `ContextPanel`), незалежна від роутингу (переживає навігацію між area), не блокує решту
  застосунку (стискає контент, без затемнення — не модальний `Sheet`). Може бути відкрита
  одночасно з `ContextPanel`. Перемикається окремою кнопкою в хедері. Жодного зв'язку з
  наявною area `Chat`/`Conversations` — окрема поверхня, окрема модель даних.
- **Розмова** — одна активна розмова на юзера, без екрана історії/списку розмов. «Нова
  розмова» скидає контекст (стара не видаляється, просто перестає бути поточною).
- **LLM-провайдер** — реалізація проти OpenAI-сумісного формату запиту (Chat Completions), без
  окремих реалізацій під конкретних вендорів на цьому етапі. Ключ і базовий URL провайдера
  конфігуруються на рівні деплойменту (env/секрети), не через UI Tenant Admin і не per-tenant.
- **Пайплайн генерації** — через `apps/worker` + наявний realtime-міст (Socket.IO/Valkey) з
  першого дня, без проміжної фази на прямому SSE з `apps/api`.
- **Джерела знань** — рівень 1: статичний контент з нової папки `docs/ai-knowledge/` (не
  наявний інженерний `docs/`), рівень 2: динамічне довантаження контенту або платформним
  суперадміном (спільно для всіх тенантів), або Tenant Admin (лише свій тенант). Робота з
  живими бізнес-даними тенанта (tool-calling) — поза скоупом базового продукту, лишається
  контриб'юторам/форкам.

## Що дослідити на цьому етапі

1. **Тематика SaaS-продукту й конкретний контент** — що саме йде в `docs/ai-knowledge/` на
   рівні 1 і що зможе довантажити superadmin/Tenant Admin на рівні 2.
2. **Конкретний бекенд за OpenAI-сумісним провайдером** — який саме (DeepSeek, Grok, MiniMax,
   OpenRouter, сам OpenAI тощо) і яка модель стають стартовими.
3. **Бюджет і захист від зловживання** — квоти токенів, rate limit на інсталяцію, поки немає
   білінгу.
4. **Токен-за-токеном рендер у v1** — чи потрібен уже зараз, чи можна почати з фінальної
   відповіді одним шматком.
5. **Зберігання розмов і приватність** — політика retention, чи є дані, яких не можна
   відправляти стороннньому LLM-провайдеру.

Результат цього етапу — план, готовий звести у фазову структуру (на кшталт `CHAT-0…4` чи
`CAL-1…4` в інших доменах цього репозиторію), не повторна дискусія про UI чи провайдера.
