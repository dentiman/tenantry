# Відомі проблеми UI-шару

Журнал проблем бібліотеки, які доводиться обходити в коді. Мета — щоб обхід був
**один і названий**, а не «костиль на кожному місці використання», і щоб було
видно, коли проблему можна закрити (вийшла нова версія — перевірити за
процедурою нижче й прибрати обхід).

## UI-1. Форм-контроли `Switch` і `Checkbox` не перемикаються

**Статус:** **закрита 2026-08-24** — не полагоджено в апстрімі, а знято разом із бібліотекою
(обидва фронти пішли з HeroUI). Обходів у коді більше немає: `cell-switch.tsx` видалений,
`SelectionCheckbox` і портал хедер-чекбокса зникли з гріда. Споживачі (`/users`, налаштування
сповіщень) беруть штатний `Switch`/`Checkbox` із `libs/ui`.

### Симптом

`<Switch>` (і `<Checkbox>`) рендериться правильно, виглядає правильно, але **не
змінює стан від дій користувача**. Жодної помилки в консолі — контрол просто
«мертвий».

### Що перевірено

Проби ставилися на `/dashboard` (поза таблицею) і в клітинці гріда `/users`.

| Перевірка                                                                       | Результат                                   |
| ------------------------------------------------------------------------------- | ------------------------------------------- |
| HeroUI `Switch` — клік по повзунку                                              | ✗ стан не змінюється                        |
| HeroUI `Switch` — клік по текстовій мітці всередині `Switch.Content`            | ✗                                           |
| HeroUI `Switch` — `Space` на сфокусованому input                                | ✗                                           |
| HeroUI `Checkbox` — клік                                                        | ✗                                           |
| **Сирий** `react-aria-components` `Switch` — клік                               | ✗                                           |
| Нативний `<input type="checkbox">` на тій самій сторінці                        | ✓ працює                                    |
| HeroUI `Button`, `Dropdown` (RAC `usePress`) — клік, зокрема в клітинці таблиці | ✓ працює                                    |
| Програмний `input.click()` на прихованому input                                 | ✓ спрацьовує, React `onChange` викликається |
| Поза таблицею vs у клітинці `Table`                                             | однаково ✗ — **таблиця ні до чого**         |
| Дублікати `react-aria-components` / `@react-aria/*` у дереві залежностей        | немає (одна копія)                          |

Розмітка, до речі, коректна — проблема не в ній:

```html
<div data-slot="switch" class="switch switch--sm" data-selected="true">
  <label data-slot="switch-content" data-react-aria-pressable="true">
    <span style="clip: rect(0,0,0,0); …"
      ><input role="switch" tabindex="0" aria-label="Active" type="checkbox"
    /></span>
    <span class="switch__control"><span class="switch__thumb"></span></span>
  </label>
</div>
```

Слухачі на `document` (capture) показують, що `pointerdown` → `mousedown` →
`click` доходять до повзунка і **не скасовані** (`defaultPrevented === false`),
але події `change` за ними не настає: `<label>` не активує вкладений input, а
RAC-обробник натискання не перемикає стан.

### Уточнення, яке легко пропустити

Окремо від головної проблеми: **`Switch.Content` обов'язковий**. Саме він —
RAC `SwitchButton`, тобто `<label>` із прихованим input усередині. Без нього

```tsx
<Switch>
  <Switch.Control>
    <Switch.Thumb />
  </Switch.Control>
</Switch>
```

у DOM приїжджає лише `div.switch` — без input, без `role`, без `aria-label`:
картинка, якої не існує для скрінрідера. Це помилка використання, а не UI-1;
але діагностуючи UI-1, спершу переконайся, що `Switch.Content` на місці —
інакше лікуватимеш не те.

### Поточний обхід

Візуал HeroUI в `inert`-обгортці (не потрапляє ні в таб-ордер, ні в дерево
доступності) + справжній нативний `input` поверх нього на всю площу:

```tsx
<span className="relative inline-flex …">
  <span inert>{/* HeroUI-візуал: Switch / Checkbox */}</span>
  <input type="checkbox" role="switch" aria-label={label} checked={…} onChange={…}
         className="absolute inset-0 z-10 size-full opacity-0" />
</span>
```

Клік і клавіатура дістаються нативному input-у, стан малює HeroUI. Доступність
зберігається: підпис на input (`aria-label`), фокус-кільце малює обгортка через
`has-[:focus-visible]`.

Обхід **не розмазаний по сторінках** — він живе у двох компонентах гріда
(`CellSwitch`, `SelectionCheckbox`); сторінки використовують їх і про проблему
не знають.

### Варіанти системного рішення

**A. Тонкий шар власних контролів (рекомендація на зараз).**
Перенести обхід із гріда в окремий модуль (умовно `components/controls/`) і
експортувати звідти `Switch`, `Checkbox`, `Radio` з нашим API. Сторінки
імпортують тільки звідти, HeroUI-контроли форм не використовуються напряму
ніде. Плюс: одне місце заміни, коли UI-1 закриють, — видаляється нутро шару,
API лишається. Мінус: свій шар треба тримати в тонусі (варіанти, розміри).
Вартість — низька: контролів мало, візуал далі HeroUI-івський.

**B. Замінити грід/таблицю.**
Не вирішує UI-1: проблема відтворюється поза таблицею й на сирому RAC. Заміна
таблиці — окреме рішення з інших причин (віртуалізація, складні колонки), і
міряти її треба окремо. Для UI-1 це не ліки.

**C. Оновити HeroUI / зафіксувати issue в апстрімі.**
v3 у бета-статусі, симптом виглядає як баг збірки чи регресія RAC-інтеграції.
Дешевий крок: перевірити на свіжій версії, і якщо відтворюється — завести issue
з мінімальним репро (воно вже є, див. «Що перевірено»). Це шлях до того, щоб
обхід прибрати назовсім, а не носити вічно.

**D. Відмовитися від HeroUI на користь іншої бібліотеки.**
Найдорожче; сенс має лише якщо таких проблем набереться критична маса. Цей
документ і є лічильником: поки в ньому один пункт — не привід.
**Частково обрано 2026-08-23:** пілот на `apps/platform-web` (shadcn/ui на Base UI) —
саме щоб зміряти вартість D на меншому застосунку, перш ніж чіпати `apps/web`.

**Рекомендований порядок:** C (перевірити свіжу версію) → якщо не полагоджено,
A (винести шар контролів) → D тільки якщо журнал розростеться.

### Як перевірити, що проблема зникла

1. Оновити `@heroui/react` / `@heroui/styles`.
2. Тимчасово покласти на будь-яку сторінку неконтрольований контрол:
   ```tsx
   <Switch aria-label="probe">
     <Switch.Content>
       <Switch.Control>
         <Switch.Thumb />
       </Switch.Control>
     </Switch.Content>
   </Switch>
   ```
3. Клікнути по ньому й перевірити `data-selected` на `[data-slot="switch"]`.
   Змінюється — UI-1 закрито: прибрати нутро обходу (нативний input + `inert`),
   лишивши публічний API `CellSwitch`/`SelectionCheckbox` незмінним, і оновити
   цей документ.
